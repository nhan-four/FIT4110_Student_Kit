# Lab 02 — OpenAPI contract-first

**Why:** a consumer should not need to read a provider’s source code to integrate. The contract is the shared, versioned agreement.

Use [FIT4110_lab02_openapi](https://github.com/TrangLe1912/FIT4110_lab02_openapi). Read the pairing matrix and correct user story; complete provider and consumer analysis independently before negotiation. Adapt the source `openapi.yaml` and negotiation log, then lint and mock it.

Deliverables: OpenAPI 3.1 contract, analysis documents, signed negotiation log (at least six decisions), lint report, five mock-request screenshots, known issues, and versioning note. Use [OpenAPI starter](../04_Templates/openapi-template.yaml) only when a new blank contract is needed.

Do not confuse a mock response with proof that authentication or business logic works. A mock proves the contract can drive an early integration conversation.
